# Community

Use [GitHub Issues](https://github.com/hannasage/projection-ui/issues) for reproducible defects and bounded feature requests.
Use [GitHub Discussions](https://github.com/hannasage/projection-ui/discussions) for questions, examples, and design feedback.
No response deadline is promised.

## Report a defect

Include the package version, framework, browser, and a small reproduction.
Describe the expected result and the actual result.
For an accessibility defect, include the keyboard or assistive technology steps.
Keep credentials and private data out of reports.

## Propose a change

Read [CONTRIBUTING.md](https://github.com/hannasage/projection-ui/blob/codex/community-and-release-docs/CONTRIBUTING.md) before implementation.
Keep reusable components in the library and application-specific compositions in consumers.
Use locally authored examples for documentation changes.
Submitted feedback does not become executable documentation.

Share example needs in [the examples discussion](https://github.com/hannasage/projection-ui/discussions/5).
Share upgrade constraints in [the preservation discussion](https://github.com/hannasage/projection-ui/discussions/6).
Read [FEEDBACK.md](https://github.com/hannasage/projection-ui/blob/codex/community-and-release-docs/FEEDBACK.md) for report paths.

For a vulnerability, use the private path in [SECURITY.md](https://github.com/hannasage/projection-ui/blob/codex/community-and-release-docs/SECURITY.md).
Do not disclose a vulnerability in a public issue.
