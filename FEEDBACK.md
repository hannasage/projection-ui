# Feedback

Use [GitHub Issues](https://github.com/hannasage/projection-ui/issues) for a reproducible bug or a feature proposal.
Use the issue forms to include the details that a maintainer needs.

## Report a bug

A reproduction is a small example that repeats a problem.
Include:

- The Projection UI, React, and React DOM versions.
- The browser, operating system, and build tool versions.
- A public reproduction or the smallest code sample that fails.
- The steps to repeat the problem.
- The expected result and the actual result.
- A screenshot or error message, if it explains the problem.

Remove tokens, private data, and customer details before you post.
For an accessibility report, name the keyboard sequence or assistive technology that you used.

## Propose a feature

Describe the user problem before the proposed API.
Show an example that needs the feature and explain how you handle the problem now.
State whether the change fits a generic library or one application's design.

## Discuss examples and compatibility

Use [the examples discussion](https://github.com/hannasage/projection-ui/discussions/5) to request clearer component or setup examples.
Use [the preservation discussion](https://github.com/hannasage/projection-ui/discussions/6) to share imports, theme overrides, and interactions that an upgrade must preserve.
Include versions and a small public example.
Keep a reproducible defect in Issues so its steps and fix stay together.

## Ask a question

For a setup question, use the question form in Issues.
Include the relevant code and versions.
Search existing reports before you open another one.

The maintainer reviews reports as time allows.
Reports do not guarantee a release date or a response deadline.
For a security concern, follow [SECURITY.md](SECURITY.md).
